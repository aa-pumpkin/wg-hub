# Архитектура WG Hub

## Обзор

```text
Браузер ──► nginx (frontend) ──► статика Vue
                │
                └─ /api ──► Fastify (backend) ──► PostgreSQL
                              ▲
                              └─ SSE-поток живых обновлений
```

Монорепозиторий на npm workspaces: `frontend/` и `backend/`. Backend один, без микросервисов. Наружу открыт только nginx, поэтому фронтенд и API живут на одном origin, и CORS не нужен.

| Слой | Технологии |
|---|---|
| Frontend | Vue 3, TypeScript, Vite, Tailwind CSS 4, Pinia, Vue Router, vue-i18n (de, en, ru), Lucide, Luxon |
| Backend | Node.js, TypeScript, Fastify 5, Zod, Prisma 6, Argon2id |
| База | PostgreSQL 17 |
| Запуск | Docker Compose |

## Структура

```text
backend/
  prisma/            схема и миграции
  src/
    config/          проверка переменных окружения
    lib/             prisma, ошибки, даты, шина живых обновлений
    middleware/      сессии, доступ к WG, CSRF
    modules/         auth, users, households, chores, shopping,
                     calendar, notes, expenses, gamification, dashboard, live
    scripts/         seed, reset-password
  test/              юнит-тесты и интеграционные на настоящем Postgres
frontend/
  src/
    components/      common/ и по модулям
    composables/     useForm, useFormat, useLive
    layouts/         AppLayout, AuthLayout
    lib/             чистая логика: деньги, сетка календаря
    locales/         de, en (en типизирован по de)
    services/        запросы к API
    stores/          Pinia
    views/           экраны
```

## Ключевые решения

**Изоляция WG.** Все маршруты с данными WG регистрируются внутри одного Fastify-плагина с префиксом `/api/households/:householdId`, и хук `requireMember` стоит на всём плагине. Новый модуль, добавленный туда, не может забыть проверку. Для чужой WG API отвечает 404, а не 403, чтобы не раскрывать её существование. Ресурсы ищутся по паре `id` + `householdId`. Интеграционные тесты пытаются пройти к чужим данным обоими способами.

**Обязанности: определение и конкретные сроки разделены.** `Chore` описывает задачу или серию, `ChoreAssignment` описывает один конкретный срок и его ответственного. Отметка о выполнении меняет только одну строку `ChoreAssignment`, поэтому серия не может завершиться случайно.

**Генерация сроков по запросу.** Вместо cron строки создаются при чтении: на 8 недель вперёд, для календаря до 400 дней. Генерация идёт в транзакции с блокировкой строки `Chore`, поэтому параллельные запросы не разводят ротацию. Просроченные сроки серии задним числом не создаются: после месяца без приложения никого не ждёт гора долгов.

**Основные задачи и круг.** У WG есть упорядоченный круг людей (`HouseholdMember.rotationPosition`) и упорядоченный список основных задач. Исполнитель считается формулой из номера задачи и номера недели от точки отсчёта (`Household.rotationAnchor`): каждую неделю задача переходит к следующему человеку по часовой стрелке. Срок всегда воскресенье текущей недели. Формула не зависит от истории, поэтому никто не получит две задачи, пока другой свободен (при равном числе людей и задач). Сдвиг круга просто двигает точку отсчёта. Изменения админа пересчитывают открытые задачи начиная с текущей недели, сделанные не трогаются. Новый участник входит в круг со следующей недели, чтобы не менять объявленное на эту.

**Заморозка.** `HouseholdMember.frozenAt`: человек остаётся в WG и на своём месте в круге, но формула его пропускает. При заморозке меняются только его открытые задачи текущей недели, у остальных неделя остаётся прежней. Просроченные становятся общими. После разморозки он возвращается со следующей недели. Заморозка заменила прежнее исключение из круга. Себя может заморозить любой участник, других только админ.

**Дополнительные задачи.** Свой ритм и свой упорядоченный список людей. Следующий срок получает идущий за предыдущим ответственным, при его отсутствии выбирается наименее загруженный.

**Вход без почты.** Логин и пароль; логин хранится в нижнем регистре. Единственный путь восстановления без почты: админ общей WG создаёт одноразовую ссылку на 24 часа. В базе лежит только SHA-256 токена. Использование ссылки завершает все сессии. Это значит, что админ WG технически может войти в аккаунт участника, а тот заметит это по выходу со всех устройств: так устроено сознательно, другого канала восстановления нет. Если пароль забыл единственный админ, есть консольный сброс.

**Режим админа.** Переключатель только скрывает элементы управления (`household.isAdmin`), чтобы админ случайно ничего не менял. Роль и проверки на сервере от него не зависят, это удобство, а не ограничение прав. Состояние хранится в `localStorage` отдельно для каждой WG.

**Очки.** При выполнении в `ChoreCompletion.points` записывается начисленное значение: полное вовремя, половина с опозданием, и последующая смена цены задачи историю не меняет. Защита от накрутки: очки назначает только админ, задачи участников стоят 0, пока админ не назначит цену; повторяющуюся задачу нельзя отметить раньше чем за неделю до срока; отмена выполнения забирает очки. Уровень, серия и награды считаются при чтении и нигде не хранятся.

**Время.** Сроки обязанностей и даты расходов хранятся как `DATE`, без часового пояса. События хранятся как моменты в UTC, а API принимает местное время WG, поэтому переход на летнее время обрабатывается на сервере. «Сегодня» всегда считается в часовом поясе WG, а не браузера.

**Деньги.** Только целые евроценты. Ввод вроде `19,99` разбирается по цифрам, без чисел с плавающей точкой. При равном делении лишние центы достаются первым участникам, так что сумма долей всегда точно равна сумме расхода.

**Покупка создаёт расход.** Отметка «куплено» с ценой в одной транзакции меняет статус товара и создаёт `Expense`, связанный через `ShoppingItem.expenseId`. Отменить чужую оплаченную покупку может только покупатель или админ, потому что это чужие деньги. Удаление купленных из списка расход не трогает: долг остаётся.

**Посудомойка.** Необязательный модуль: `Household.dishwasherTarget` равен null, пока админ его не включит. Цикл заканчивается, когда сумма отметок всей WG достигает цели, на сервере в транзакции с блокировкой строки WG, чтобы двое не завершили один цикл. Корона достаётся тому, у кого больше всех; при равенстве тому, кто набрал это число раньше. Страйк не получают замороженные и те, кто вступил во время цикла. Страйк снимает очки (`DishwasherStrike.points`), итог может уйти ниже нуля, уровень при этом остаётся первым и может снизиться.

**Живые обновления.** SSE-поток сообщает только имя изменившегося модуля, а клиент перечитывает данные обычным проверенным API. Через поток не проходят сами данные, поэтому права проверяются в одном месте. Шина работает в памяти одного процесса; для нескольких экземпляров backend её надо заменить на Postgres LISTEN/NOTIFY.

**Валидация в одном месте.** Формы проверяет backend (Zod) и возвращает коды ошибок по полям, а фронтенд переводит их и показывает под полем. API вообще не возвращает текстов для пользователя, только стабильные коды.

**Безопасность.**
- Пароли: Argon2id.
- Сессии: случайный токен в cookie с `HttpOnly` и `SameSite=Lax`, плюс `Secure` за HTTPS. В базе лежит только его SHA-256.
- CSRF: `SameSite` плюс проверка `Origin` на всех изменяющих запросах; API принимает только JSON.
- Лимиты на вход, регистрацию, смену пароля и приглашения.
- Заметки выводятся как текст, HTML не интерпретируется.
- CSP без inline-скриптов.
- Шрифт лежит в сборке, а не грузится с Google Fonts: для Германии это ещё и вопрос DSGVO.

## База данных

```text
User ─┬─ Session
      ├─ PasswordResetToken
      └─ HouseholdMember ─ Household ─┬─ HouseholdInvitation
                                      ├─ Chore ─┬─ ChoreRotationMember
                                      │         └─ ChoreAssignment ─ ChoreCompletion
                                      ├─ ShoppingItem
                                      ├─ CalendarEvent ─ CalendarEventParticipant
                                      ├─ Note
                                      ├─ Expense ─ ExpenseParticipant
                                      └─ ExpenseSettlement
```

Полная схема: `backend/prisma/schema.prisma`. Записи WG удаляются каскадно вместе с ней.

Правила, которые держит сервер:
- В WG всегда есть хотя бы один админ.
- Нельзя выйти или быть удалённым с ненулевым балансом: долг остался бы без человека.
- Когда уходит последний участник, WG удаляется.
- Открытые задачи ушедшего передаются остальным, история остаётся с его именем.

## UX-концепция

Минимализм: нейтральный тёплый фон, один приглушённый зелёный акцент, пастель только там, где она несёт смысл (цвета заметок, аватары, типы событий в календаре).

- **Десктоп:** боковая панель, контент, кнопка добавления в шапке страницы.
- **Телефон:** нижняя навигация из пяти пунктов, плавающая кнопка под большим пальцем, формы в виде нижней шторки, области нажатия от 44 px. На телефоне календарь открывается списком, потому что месячная сетка там слишком плотная.
- **Сетка:** на всех экранах с двумя колонками они равной ширины; карточки в одном ряду равной высоты; страницы настроек и профиля по центру.
- **Язык:** переключатель на экране входа, в боковой панели и в разделе «Ещё»; выбор хранится в аккаунте и следует за человеком на любое устройство.
- **Состояния:** скелетоны при загрузке, пустые экраны с подсказкой, повтор при ошибке, тосты, подтверждение опасных действий.
- **Оптимистичный UI:** отметка покупки и выполнения задачи срабатывают сразу и откатываются при ошибке. Расходы всегда ждут ответа сервера.
- **Доступность:** нативный `<dialog>` (ловушка фокуса, Esc), клавиатурное меню, подписи для иконок, `prefers-reduced-motion`.

## Отступления от первоначального плана

| План | Сделано | Почему |
|---|---|---|
| Готовая библиотека календаря | Свой календарь: месяц, неделя, список | Своя реализация даёт часовой пояс WG вместо браузерного, минималистичный вид и удобство на телефоне без лишней зависимости |
| Backend: Node.js | Конкретно Fastify | Встроенное разделение плагинов и даёт единую точку проверки доступа к WG |
| Авторизация: email и пароль | Логин и пароль, сброс через ссылку от админа | Почта не нужна. Заодно не нужен почтовый сервер |
| Языки: de, en | Добавлен русский, язык определяется по браузеру при первом входе | Так удобнее в реальной WG |
| Категории задач и покупок | Убраны из интерфейса, редкие поля спрятаны под «Ещё настройки» | Форма была перегружена, категория ни на что не влияла |
| Любая задача с любой ротацией | Основные (круг, еженедельно, управляет админ) и дополнительные | Так удобнее в реальной WG |
| Статусы Pending / Completed | Добавлен Skipped | «В этот раз пропускаем» не должно считаться ни выполненным, ни вечно просроченным |
| Загрузка аватара | Инициал на цветном фоне, эмодзи для WG | Не нужно хранилище файлов, бэкапы и проверка загрузок ради небольшой пользы |
| Заметки: удалять только свои | Удалять и архивировать может также админ | Иначе в общей WG некому убрать чужую устаревшую или неприятную запись. Текст чужой заметки админ менять не может |

Сверх плана: очки, уровни, серии и награды, выбор «наименее загруженного» при старте ротации, передача задачи другому человеку на один срок, предложения минимального набора переводов для погашения долгов, сброс пароля через консоль.

## Что не сделано

- **Push-уведомления.** Нужны VAPID-ключи, HTTPS и планировщик напоминаний. Архитектуре это не мешает.
- **Удаление аккаунта.** Для публичного сервиса в Германии это потребуется по DSGVO, как и Impressum с Datenschutzerklärung.
- **Редактирование расхода с бывшим участником.** Сервер примет только текущих участников WG; такой расход можно удалить и завести заново.
